# IR-021 Google Flash-Lite Guard-Rate Proof

**Finding:** two Google Flash-Lite conservative guard rates did not represent the current high-side text-token pricing path used by TokenTotals' pre-flight reservation logic  
**Classification:** CONFIRMED SAFETY / PRICING-INTEGRITY DEFECT — REPAIRED AND REVALIDATED  
**Repair branch:** `sol/forensic-hardening`  
**Revalidation date:** 2026-09-15

## How this was found

This defect was found during a stop-the-line review of `MODEL_COMPARISON_MATRIX.md` and the README pricing table. The review was prompted by stale GPT-4o/o1/o3-mini-era rows still visible on the repository's unmerged `main` branch.

The hardening branch already had the newer model family, but the matrix was expanded to expose both the ordinary base estimate and the conservative pre-flight reservation. Rechecking those guard rates against the current official Google pricing page exposed two mismatches that the previous daily source checker could not detect because it validated only Standard/base rates.

## Defect

The checked-in catalog previously represented:

```text
gemini-3.5-flash-lite
  base:  $0.30 input / $2.50 output per 1M
  guard: $0.594 input / $2.75 output per 1M

gemini-3.1-flash-lite
  base:  $0.25 input / $1.50 output per 1M
  guard: $0.55 input / $1.65 output per 1M
```

The base/Standard text-token rates were still valid. The problem was the conservative guard layer.

For the represented Google text path, the current official Priority non-global pricing section publishes the higher text-token values used by the corrected guard:

```text
gemini-3.5-flash-lite
  guard input:  $0.594 / 1M
  guard output: $4.95 / 1M

gemini-3.1-flash-lite
  guard input:  $0.495 / 1M
  guard output: $2.97 / 1M
```

For Gemini 3.5 Flash-Lite, the old `$2.75` output guard reflected a Standard non-global output rate rather than the higher represented Priority non-global rate.

For Gemini 3.1 Flash-Lite, the old `$1.65` output guard likewise did not cover the represented Priority non-global text-output rate. The old `$0.55` input guard did not align with the current high-side text-input path used by the text estimator; the corrected text guard is `$0.495`. Audio is a different billing modality and is not silently folded into TokenTotals' current text-token estimate.

## Why it mattered

TokenTotals uses guard rates before egress to reserve a conservative amount against the configured budget. A guard that is lower than a published service-mode/geography rate the transaction may use can under-reserve the request even when the base display estimate is correct.

That is a runtime safety issue, not merely a stale-document problem.

TokenTotals still does not claim that the guard is the absolute maximum across every provider product, modality, tool, account, or future billing rule. The guard is the high-side rate for the published text-token dimensions explicitly represented by the catalog and validator.

## Repair

`pricing_catalog.json` now contains:

```text
gemini-3.5-flash-lite
  base:  $0.30 / $2.50
  guard: $0.594 / $4.95

gemini-3.1-flash-lite
  base:  $0.25 / $1.50
  guard: $0.495 / $2.97
```

The generated 10,000-input / 2,000-output comparison therefore changed only the conservative-reservation examples for these rows:

```text
gemini-3.5-flash-lite
  base estimate:              $0.008000
  conservative reservation:   $0.015840

gemini-3.1-flash-lite
  base estimate:              $0.005500
  conservative reservation:   $0.010890
```

The ordinary base estimates did not change because their Standard/base rates were not the defect.

## Daily source-check repair

The earlier `matrix_source_check.py` checked Anthropic and Google base/Standard rows against the official provider pages. It did not validate the catalog's conservative guard fields, which is why the bad high-side values could survive while the daily base-rate check remained green.

The validator now uses two distinct provider scopes:

- **base-rate scope** — Anthropic model-pricing / Google Standard sections;
- **guard-rate scope** — the provider section from which the represented conservative guard is derived. For Google this revision validates the guard against the Priority pricing table.

The checker remains non-destructive. A mismatch fails the workflow for review; it does not rewrite or promote a new rate automatically.

A dedicated negative regression test deliberately restores the old Gemini 3.5 Flash-Lite `$2.75` guard while the fixture's Priority section contains `$4.95`. The validator must fail with a guard-output mismatch rather than accepting the lower Standard value.

## Public pricing surfaces

The same stop-the-line repair also removed independent hand-maintained comparison tables:

- `MODEL_COMPARISON_MATRIX.md` is generated from `pricing_engine`;
- the marked README pricing snapshot is generated by the same code;
- CI requires both public surfaces to equal generator output from the checked-in verified pricing view;
- CI explicitly rejects return of the old GPT-4o/o1/o3-mini/Claude-3.x/Gemini-2.x comparison rows.

This means the README cannot quietly drift below the fold while the matrix remains current, or vice versa.

## Remaining boundary

TokenTotals is an independent approximation and pacing system, not a provider invoice engine. The current guard calculation covers the text-token pricing dimensions deliberately represented by the catalog. Separate modalities, hosted tools, grounding/search, storage/runtime meters, account-specific terms, future pricing modes, or other provider billing events must be separately modeled before TokenTotals can claim to include them.
