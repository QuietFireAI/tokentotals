# TokenTotals v2.6.0 — User-Zero Chat Discoverability Receipt

Date: 2026-09-16
Status: OPEN UX FINDING
Related validation: `2026-09-16_user-zero-v2.6.0-installation-validation.md`

## Finding — Turn Receipt Chat is not automatically surfaced after launch

### First-user observation

After launching the pinned v2.6.0 Windows candidate, TokenTotals starts its local service and tray application. The tray icon is visible and its default click action opens the local dashboard. The primary Turn Receipt Chat is available separately at `/chat` on the selected localhost port.

A first-time user therefore needs prior knowledge of the localhost URL, documentation telling them to open it, or another explicit navigation path before reaching the primary `Question → Answer → Turn Receipt` experience.

### Current runtime behavior

The Windows desktop runtime starts the local server and tray icon. Its startup notification reports the active localhost port and tells the user to click the icon to open the Dashboard. The tray default action opens `/dashboard`. The runtime does not automatically open `/chat` after startup.

Refreshing or hard-refreshing an unrelated browser page such as ChatGPT, Gemini, or another provider site does not attach TokenTotals to that page. TokenTotals is not currently a browser extension or browser-wide interception layer. A refresh would only help if the browser were already pointed at the TokenTotals localhost page while the local service was unavailable.

The `New thread` control belongs to TokenTotals' built-in local chat. It creates a new TokenTotals thread and does not attach TokenTotals to an existing provider-browser conversation.

### Diagnosis

This is a first-run discoverability/onboarding defect, not a proxy/accounting defect. The primary product experience is the Turn Receipt Chat, but the current desktop launch path surfaces the supporting dashboard first and requires the user to discover `/chat` separately.

### Minimal follow-up candidate

Without redesigning the proxy architecture:

1. After a successful first desktop launch and local-server readiness, automatically open the Turn Receipt Chat at the actual selected localhost port in the user's default browser.
2. Add an explicit `Open Turn Receipt Chat` action to the tray menu.
3. Keep the dashboard available as the secondary diagnostics/control surface.
4. Do not attempt to inject TokenTotals into arbitrary existing browser tabs; that would be a different architecture and is out of scope for this repair.
5. Re-test first launch with a user who is not told any localhost URL.

### Acceptance criterion

A first-time Windows user who runs `TokenTotals.exe` should reach the Turn Receipt Chat without knowing, typing, or discovering `127.0.0.1`, port `8080`, or the `/chat` route.

The pinned v2.6.0 binary is not modified during this evidence run; this receipt records the behavior observed in that candidate for a later minimal repair/rebuild.
