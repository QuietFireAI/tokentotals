## Scope

Validate the complete first-user path on Windows using the project's own instructions and the packaged executable, without assuming CI or packaged smoke results prove end-user usability:

`download → extract → TokenTotals.exe → Windows/security behavior → local app → /chat → provider/API credential → real prompt → unchanged model answer → Turn Receipt beneath answer → Standard/Expanded → new thread → CSV audit export → shutdown/restart → removal instructions`

After the local/user-zero path, provider interoperability is to be exercised in this order unless evidence changes the plan:

1. Gemini Free Tier
2. OpenRouter free models
3. Anthropic API

For each provider preserve raw available telemetry, canonical Turn Receipt, rendered receipt, exported CSV, discrepancies, missing fields, latency/settlement behavior, and exact provider/model identity.

## Product invariants under test

- The model answer is followed directly in conversational flow by its Turn Receipt.
- Standard is the default receipt presentation.
- Expanded exposes deeper turn/thread economics without changing the underlying canonical receipt.
- Receipt footer is `TurnReceipt.com`.
- Missing telemetry remains unavailable and is never fabricated as zero.
- Provider/model identity is preserved.
- TokenTotals does not claim provider-invoice exactness or official provider partnership.
- Private provider/observability launch-partnership strategy is out of scope for this public-repo validation.

### UZ-01 — Installation/User Guide is not discoverable from the v2.6.0 release surface

**Observed by first-time user:** The public TokenTotals v2.6.0 release exposes `TokenTotals_Windows_v2.6.0.zip`, but the tester could not find the promised installation/User Guide from the release page or download area. Without prior project knowledge, the tester did not know the next installation step.

**Download result:** ZIP downloaded successfully with no warning/blocking message. Filename remained `TokenTotals_Windows_v2.6.0.zip`.

**Diagnosis:** This is a documentation/discoverability defect. The v2.6.0 release body describes the Windows package and names `TokenTotals.exe`, but provides no installation/User Guide link. The candidate packaging workflow also did not place a User Guide in the ZIP. A plain-language `USER_GUIDE.md` existed in the separate post-v2.6 usability work (PR #2), but it was not part of the candidate source commit or release artifact.

**Focused repair:** Reused the already-written plain-language User Guide rather than inventing a second guide. Added `USER_GUIDE.md` to public `main` and added a prominent README entry point: `Start with the plain-language User Guide`. No CSV/runtime implementation, helper workflow, receipt-accounting logic, or architecture from PR #2 was merged as part of this repair.

**Repair recheck finding:** The first documentation import also contained PR #2's future CSV-export section even though CSV export is not present in the v2.6.0 candidate/current runtime. That recheck failed. The unsupported CSV section was removed before accepting the documentation repair.

**Guide recheck:** The public User Guide now truthfully gives the Windows first-start path for this candidate: download the ZIP, extract it, run `TokenTotals.exe`, then use the local TokenTotals surfaces. It does not claim the unmerged CSV-export feature.

**Remaining blocker:** The v2.6.0 **release page itself still does not link to the User Guide**. Therefore a first-time user arriving only at the release page remains stranded even though a correct public guide now exists in the repository. This item is not considered fully closed until the release page visibly links to the guide and a user-zero recheck confirms the link is discoverable.

**Candidate integrity:** The tested ZIP was not modified or replaced during this documentation repair; the candidate identity recorded above remains the evidence target for this run.

### UZ-03 — Microsoft Defender SmartScreen interrupts first launch

**Observed result:** On first launch of `TokenTotals.exe`, Microsoft Defender SmartScreen displayed `Windows protected your PC` and stated that an unrecognized app was prevented from starting. The dialog identified:

- App: `TokenTotals.exe`
- Publisher: `Unknown publisher`
- Choices shown: `Run anyway` and `Don't run`

The tester deliberately chose to continue. TokenTotals subsequently launched.

**Diagnosis:** This is a real Windows distribution/trust-friction finding. It is not evidence that the executable is malicious, and it is not an installer failure; the v2.6.0 distribution is a portable ZIP and SmartScreen interrupted the executable's first launch. The visible `Unknown publisher` state means the candidate does not present a recognized publisher identity to Windows SmartScreen.

**Candidate-handling decision:** Do not rebuild, replace, or sign the candidate in the middle of this pinned run because doing so would change the binary identity under test. Preserve the warning as part of the v2.6.0 user-zero evidence.

**Release follow-up:** Before a general public release, decide whether the Windows artifact will be code-signed and ensure first-run documentation accurately tells users what Windows may display and how to verify the published artifact hash before making their own run decision. Do not normalize bypassing a mismatched or unverified download.

**Status:** OPEN distribution/documentation follow-up; runtime test may continue against the already-pinned candidate because the tester explicitly chose to run this exact candidate.

**Screenshot evidence:** `Screenshot 2026-09-16 135349.png`; 61,019 bytes; SHA-256 `5d9307759915b2cc4aa9e6cd5b5e5e7febb579c0781a11f1381f4e530b892871`.

### UZ-06 — `Raise Local Threshold +$5` lacks strong visual change confirmation

**Observed by first-time user:** Clicking `Raise Local Threshold +$5` changes the threshold total displayed to the left, but the change can be easy to miss unless the user is already watching the number.

**Usability finding:** A brief, subtle visual pulse/highlight on the changed threshold value would make successful activation immediately perceptible without requiring the user to stare at the numeric field. The requested behavior is feedback only; it should not change pacing/accounting semantics.

**Classification:** Non-blocking usability improvement. It does not invalidate the successful dashboard/runtime start and does not require changing the pinned v2.6.0 binary during this validation run.

**Follow-up candidate:** Add a short visual pulse/fade to the threshold value when a threshold update succeeds, then regression-test that the effect is presentation-only and the threshold changes exactly once per successful action.
